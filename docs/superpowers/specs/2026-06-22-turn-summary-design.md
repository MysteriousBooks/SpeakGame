# 回合总结与诏令暂存系统设计

## 概述

改进崇祯多Agent社会模拟游戏的回合流程，解决"发布诏令后直接进入下一回合"的问题。引入诏令暂存机制，支持多条诏令汇总后一次性执行，并以结构化卡片展示回合结果。

## 交互流程

### 诏令暂存

```
输入框: [裁撤冗员                    ] [颁诏]
                                        ↓
📜 待颁诏书（2道）:
  1. 裁撤冗员                        [撤销]
  2. 赈灾拨银十万                    [撤销]

[清空待颁]              [下一回合 ▶]
```

1. 用户在输入框写诏令，点击**"颁诏"**按钮
2. 诏令加入"待颁诏书"列表，显示在输入框下方
3. 可继续写多条诏令，每条都可单独**撤销**
4. **"清空待颁"** 按钮一键清除所有待颁诏令
5. 点击**"下一回合"** → 所有待颁诏令汇总为一道诏书发送到服务器

### 回合执行

1. 前端将待颁诏令合并为多行文本（如 `1. 裁撤冗员\n2. 赈灾拨银十万`）
2. POST 到 `/next_turn` 端点（现有接口不变）
3. 服务器执行：早朝 → 诏书执行 → 史官推演 → 时间推进
4. 结果通过 SSE 流式返回

## 前端改动

### index.html

**HTML 结构改动：**
- 表单区域：输入框 + "颁诏"按钮 + "下一回合"按钮
- 新增"待颁诏书"展示区域（在输入框下方）
- 新增"清空待颁"按钮

**JavaScript 改动：**
- `pendingEdicts: string[]` — 待颁诏令数组
- `issueEdict()` — 颁诏：将输入内容加入 pendingEdicts，更新展示
- `removeEdict(index)` — 撤销单条待颁诏令
- `clearEdicts()` — 清空所有待颁诏令
- `nextTurn()` — 修改：合并 pendingEdicts 为多行文本，发送到服务器
- `renderTurnResult(data)` — 新的回合结果渲染函数，结构化展示
- `renderHistory()` — 改造：按结构化卡片渲染历史回合

**CSS 改动：**
- 待颁诏书列表样式
- 回合结果卡片各章节样式
- 财政高亮样式（红色/绿色）

### 财政高亮规则

| 字段 | 高亮规则 |
|------|----------|
| 国库、内帑 | 红色(减少)/绿色(增加)，带图标 |
| 月收入、月支出 | 红色(减少)/绿色(增加)，带图标 |
| 民心、军力 | 绿色(正值)/红色(负值) |
| 其他数值 | 普通 delta 样式 |

## 后端改动

### 无需改动

- `/next_turn` 接口不变，已接受 edict 文本
- `/court/end` 接口不变
- `GameEngine.finish_turn()` 不变
- `TurnSummary` 数据结构不变
- 回合历史存储不变

### 回合历史数据增强

`turn_history` 中已包含完整数据（era, edict, narrative, delta, court_speeches, execution_public, events 等），前端按结构化格式渲染即可。

## 回合历史

刷新页面后，`renderHistory()` 按同样结构化卡片格式渲染历史回合，确保刷新前后体验一致。

## 实现范围

仅涉及前端（index.html）改动，后端无需修改。具体：
- `src/web/templates/index.html` — 全部改动
